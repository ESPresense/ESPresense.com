:::caution[New page]
Pin data comes from the vendor's docs and schematics and hasn't been checked on hardware yet. The **Templates** page and the `eth` setting in templates need firmware with [ESPresense#2531](https://github.com/ESPresense/ESPresense/pull/2531). On older firmware, pick the Ethernet Type on the Network page and copy the pins into the Hardware page by hand. Firmware built from `main` since the ESP-IDF port also needs [ESPresense#2537](https://github.com/ESPresense/ESPresense/pull/2537): without it this board's Ethernet clock comes out on the wrong pin and Ethernet never links. Release v4.0.6 is fine.
:::

## Notes

- **Which Ethernet Type?** Pick **ESP32-POE** (`eth` 2) for both the ESP32-POE and the ESP32-POE-ISO; Olimex's own ESPHome configs use the same settings for both. **ESP32-POE_A1** (`eth` 12) is the same with PHY address 1, added for some newer boards. Olimex doesn't document an "A1" revision, so only try it if 2 never gets a link.
- **Non-ISO boards: never plug USB into a computer while the board is powered by PoE.** Olimex warns this can damage the board, the computer or both. The ISO version is isolated (3000 V) and doesn't have this problem.
- Buy the WROOM version. The WROVER (PSRAM) versions move the Ethernet clock to GPIO 0, which ESPresense doesn't have an entry for.
- All four LEDs (power, charge, link, activity) are wired in hardware, so there's no status LED to configure.
- BUT1 is on GPI 34, an input-only pin with an external pull-up, so the template uses pin type *Floating Inverted*.
- I2C is set to the UEXT connector (SDA 13, SCL 16), which has 2.2 kΩ pull-ups on board. The plain `esp32` build defaults I2C bus 1 to GPIO 21/22, which are Ethernet pins, so Ethernet fails to start ([#2510](https://github.com/ESPresense/ESPresense/issues/2510)).
- GPIO 18, 19, 21, 22, 23, 25, 26 and 27 belong to Ethernet (RMII and MDIO/MDC). Don't put sensors on them. GPIO 12 (PHY power) and 17 (clock) too.
- PoE is IEEE 802.3af. The ISO can supply about 2 W to add-ons, the non-ISO about 4 W.
